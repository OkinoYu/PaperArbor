# Series / 技术演进

系列是一组针对持续约束的不同选择，不是每代更强的预设故事。核实继承关系、版本与范围；官方代码/配置补充与完整论文精读分开。

## 双层阅读

先快速定位具体问题、范围、时间线与贯穿差异，再提供能独立恢复机制的代际深读。不要为压到若干屏而删训练、推理和公式解释；总览表只留重要维度，细节下放。

- **时间线**：首发、模型发布、代码日期标明类型；非等比例注明。日期不是性能轴。
- **共同骨架**：真实输入输出路径，解释各阶段职责；分叉系列不强行宣布共同核心。
- **代际单元**：上一代约束 → 保留/替换/新增/仍未解决。原始架构图配导读，再拆计算步骤；训练、推理、结果与边界不能被“同前代”吞掉。
- **相邻对照**：比较信息形态、连接、位置、训练信号与计算，不串总分；删除/绕过旧模块明确写出，不假设创新永久累加。
- **贯穿线**：多个变化共同影响能力；消融支持机制，横评支持系统结果。对齐 pairs/samples/tokens 与总/激活参数。

方法按 [mechanisms.md](mechanisms.md)。公式首次完整解释，后续指出对象/条件变化。原图与重绘互补；无原图/资料不足说明范围，不画虚构架构。

## 交互职责

代际选择器比较同一计算环节；无 JS 时所有面板可读，不隐藏反例或评测条件。给详细机制和实验的跳转。

已有 Single 可复用结构，承重事实仍核对主来源。按 [quality.md](quality.md) 验收：读者能解释相邻两代为何改变、数据流哪里改变、哪些结论不能归因。
