# 方法、训练、推理与公式拆解

用于 Single / Series。让读者跟踪一个样本走过模型，解释中间状态为何变化。以下问题不必机械排成标签；用连贯段落回答，需要比较时用表。

## 从问题到真实路径

选择贯穿的具体任务。解释哪里失败、失败的机制、作者改变哪个环节。类比后立即回到真实对象；“记忆”“专家”“推理”不能替代张量或算法定义。

先交代端到端路径，区分训练与测试；再按计算依赖拆步骤，而非按术语介绍。每个承重模块回答：

| 问题 | 最少应交代的内容 |
| --- | --- |
| 输入 → 输出 | 图像、token、特征、状态或概率；形状只给已核实或明示符号推导。序列长度与通道宽度分开。 |
| 内部变换 | 哪些对象匹配、合并、更新或采样；运算顺序、mask、跨层连接与保存的状态。 |
| 为什么需要 | 改变的约束；作者理由给出处，编辑分析明确标记。 |
| 如何学习 | 数据、目标、梯度更新到哪些模块、冻结/stop-gradient、监督位置；纯推理模块说明无训练信号。 |
| 测试如何用 | 条件输入、初始化、缓存、迭代终止、工具环境与额外开销。 |
| 证据与边界 | 控制实验或诊断；无消融不补因果结论。 |

“去掉模块会怎样”要区分数学必然、作者测到和待验证三类。组合模块要解释连接处，不只分别定义名称。

## Training

按阶段交代 **数据 → 可训练参数 → 目标/监督 → 阶段衔接**。清洗后集合、消费 samples/pairs/tokens 与监督位置是不同对象。合成数据交代生成器与筛选器；开放数据名不等于完整数据可得。

Loss 说明对象、优化方向、权重、mask 与归一化；蒸馏核实教师/student 分布、采样来自谁、KL 方向。RL 区分 rollout、奖励、目标与更新，不自动补 GRPO。分开教师训练、蒸馏、后训练与测试扩展。

配方缺失时列最影响复现的缺口。配置的辅助 loss 字段不是整个训练目标。

## Inference

走通输入 → 预处理 → prefill/特征 → 生成/循环 → 输出。标明训练专用组件、测试保留组件、缓存/状态与停止条件。工具参数生成与实际执行分开。

成本分视觉编码、prefill、decode、权重、缓存与多轮执行。复杂度只描述推导的操作，不等同实测速度。推荐采样参数不等于全表评测协议；原生上下文训练与外推分开。

## 公式解释

只保留能解释目标、更新、路由或约束的公式。紧邻编排 **公式 → 中文操作含义 → 符号/形状 → 设计作用 → 来源与省略项**。

- 原文式保留编号与 locator，核实上下标、条件与求和域。
- 说明式写明根据何种机制等价/简化，省略 norm、投影、batch 等，不冒充论文式。
- 符号定义一次，改变意义时提醒；概率、logit、embedding 与离散 token 不互换。
- 状态更新核对矩阵方向；损失解释最小化使什么变大/小。反事实检验方向，不能虚构分数。
- MathML 加可读 aria-label，文字保留完整解释。不存在公开公式就用机制文字。

## 实验支持什么

主结果检查协议下的系统表现；消融检查控制条件后的改动；诊断检查机制是否按预期工作。每条结论选恰当证据，而非最高分。

保留 checkpoint、split、指标方向、精度、分支、采样/工具设置和来源。不对齐的比较列明差异；跨版本分数不证明模块因果或数据效率。解释负例和非单调结果；没有受控证据就说明只支持系统结果。
