01 · 导读：把拒绝能力蒸馏进去，把干预留在训练端

核心判断

SafeSteer 把同一基座的“过度拒绝版本”当作训练教师，在学生自己生成的有害请求轨迹上，只比较一小组安全相关词表 token 的概率。它试图吸收拒绝行为，同时少扰动原有问答、数学和代码能力。最有价值的是这条局部监督路径；“完全消除 alignment tax”则比实验能支持的结论更强。

论文为 SafeSteer: Localized On-Policy Distillation for Efficient Safety Alignment，作者 Hao Li、Jingkun An、Zijun Song、Pengyu Zhu、Rui Li、Hao Wang、Wendi Feng、Yesheng Liu、Lijun Li、Jin-Ge Yao、Lei Sha。本次固定精读用户提供的完整 PDF：arXiv v2，版本日期 2026-08-21；首发日期为 2026-06-01。正文和附录均已阅读，辅以官方代码的固定提交做静态核对；未运行训练或复现实验。[PDF p.1；arXiv submission history]

理解机制：总览 → 教师 → 词表子集 → 局部损失。评估结论：实验口径 → 主结果与反例 → 复现边界。

本文以 OPD（On-Policy Distillation，基于当前学生轨迹的蒸馏）为主线。教师与学生从同一指令模型初始化，教师的额外能力来自 activation steering（激活引导），而非更大参数量；模型名中的 3B/4B/7B/8B 沿用 checkpoint 名称，原文没有另给精确参数审计。[§3.1–3.4, pp.3–4；§4.1, p.5]

02 · 动机：安全教师可以可靠，却不适合直接部署

Alignment tax 指安全对齐后一般任务能力受损。论文的动机是：混入大量通用数据、额外奖励模型或限制优化方向，都在付出额外成本；如果拒绝相关信号在输出分布中较稀疏，是否可以缩小监督范围？这是一条设计假设，不能把“安全 token 较少”直接等同于“安全与能力在参数空间完全分离”。[§1–2, pp.1–2]

贯穿案例是一个无害请求：“怎样简单清洁淋浴喷头？”激活引导教师竟把清洁解释成危险行为而拒绝；训练后的学生与基座仍给出实质回答。这个反差揭示了工作分工：教师负责提供强拒绝信号，学生才是部署对象。[Appendix D.3, p.14]

先看图里的 πₜ，再看 πₛ：教师“更安全”在这里来自强制拒绝，不能独立说明它更有用。SafeSteer 的难点正是避免把教师对无害问题的普遍拒绝一并复制。普通 SFT 匹配整条目标文本，完整词表蒸馏匹配全部分布；本文缩小到经筛选的词表维度，并只在有害请求上更新学生。[§3.2–3.4, pp.3–4；Appendix D, pp.13–15]

03 · 总体路径：两类数据，两种轨迹，一份可部署学生

原图从左往右读：左侧把拒绝向量注入基座，形成 πₜ；中间用它对无害请求生成拒绝前缀，与未引导基座逐位置比较，产出全局安全 token 集合 S；右侧在学生当前轨迹上比较教师和学生在 S 上的概率。右下的 “Keep Unconstrained” 表示没有对 S 外逐项施加同一匹配损失，并不保证那些概率完全不变。原图省略了两种轨迹来自谁，以及 loss 的归一化；下面补上。[§3.2–3.4, pp.3–4]

04 · 安全教师：在残差流里持续加入拒绝方向

输入是有害与无害指令。作者沿用 refusal-direction 方法，通过比较基座在两类指令上的隐藏表示提取向量 d，并选择注入层 ℓ。它不是新训练出的分类器，也没有外部强教师的权重。正文给出的核心干预是：

hℓ⋆=hℓ+d

hℓ 是进入第 ℓ 个 Transformer block 的残差流，d 与模型隐藏宽度一致；forward pre-hook 在 block 接收输入之前加上 d，后续层处理修改后的表示。该向量注入序列所有 token 位置，既包括提示又包括生成时的前缀，持续提高拒绝倾向。它不会修改教师权重。正文没有给各 checkpoint 最终层号和方向范数，不能据式子补成任意通用超参。[§3.1, Eq.(1), p.3]

官方实现先采样训练/验证指令，再筛选样本、产生 candidate directions、在验证样本上选方向，最后挂教师 hook。标准运行脚本设置 freeze_teacher=True、update_refusal_vector=False、freeze_safe_token=True；教师不是随学生同步的 EMA 教师。[code d9f7822 · distil_trainer.py:810–929；scripts/run_*.sh]

分析判断

这个教师提供的是基座已有拒绝能力的强化版本，不能凭空补齐模型不知道的安全概念。它近乎总拒绝的行为适合制造对比信号，却不构成“安全判定器”；原文也把基座已有拒绝能力列为前提。

[§3.1, p.3；§7, p.9]

05 · 安全 token：沿教师拒绝前缀，对比概率再投票

先固定相同前缀，才比较两个分布

对一个无害指令 x，由教师采样 N 条长度受 H 限制的拒绝轨迹 r。把同一条轨迹前缀送给教师与未引导基座，取得每一步对全词表 V 的条件概率。比较的是“同一上下文里，注入拒绝方向让哪些候选 token 更可能”，并非比较两模型各自生成文本的频率。

Δj(x,n)(v)=logpt(v|x,r<j(n))p0(v|x,r<j(n))

v 是候选 token ID，j 是生成位置，n 是轨迹编号；Δ 大意味着教师相对基座更偏好它。必须先对完整词表得到 log-probability；logit 差缺少两个 softmax 归一化常数，不应当混写成 Eq.(2)。这里的“安全”是对拒绝方向敏感的操作定义，不能保证每个入选 token 独立具备语义安全性。[§3.3, Eq.(2), p.3]

局部 Top-K′ 投票，汇总成全局 Top-K

每个有效“指令 × 轨迹 × 位置”各取 Δ 最大的 K′ 个候选 token，给它们各一票；跨指令、轨迹、位置累计票数，最后选得票最高的 K 个 ID。Eq.(3) 是指示函数求和，Eq.(4) 是在固定大小集合中最大化累计票数。投票让单次极端概率比不容易支配平均排名；原文未给独立的 vote-vs-mean 受控性能表，不能据设计动机声称已经量化其增益。[§3.3, Eqs.(3)–(4), p.4]

配方区分两个 K：每一步候选 K′=200，最终 |S|=50；教师采样 N=8、温度 1.0；Qwen 的 H=7，Llama 的 H=5。S 是模型级固定集合，跨训练样本与位置使用，并非每一步按教师最大概率动态选 50 个 token。[Appendix A.1, p.12]

先看左侧 Sorry、Unfortunately，再看右侧 illegal、unethical：更长前缀接触到拒绝理由，选出的 token 更接近安全语义。这是词表组成诊断，词云不能作为每个 token 精确权重的读数，也不能单独证明学生已形成“深层安全推理”。[§5.2, p.8；Figure 4]

官方 token-selection 函数还剔除特殊 token 与平均教师概率低于阈值的 token，再对有效位置投票；这些过滤在主公式中没有展开。实现生成 H−1 个续写 token，再对 H 个预测位置评分；H 是挖掘窗口，不是训练学生的最大回复长度。[code d9f7822 · utils/select_safe_tokens_via_activation.py:10–82, 132–289]

06 · 局部 reverse KL：比较候选词概率，保留绝对质量

训练轨迹来自当前学生

给有害指令 x，当前 πₛ 先生成 M 条完整回复 y。对每条学生前缀 y<t，教师和学生都给出下一 token 分布 pₜ 与 pₛ。学生即使已朝不安全方向续写，教师也要在这个实际前缀上给监督；这正是 on-policy 的含义。教师不会用自己另写的拒绝文本替换学生轨迹。[§3.4, Eq.(5), p.4]

完整 reverse KL 以学生概率加权，在整个 V 上求和；本文把求和域改为 S：

Lt(m)(θs)=∑v∈Sps(v)logps(v)pt(v)

θₛ 是学生参数；pₛ、pₜ 均来自完整词表 softmax，然后按 token ID 取切片，S 内的概率和可以小于一。它既不是只对轨迹里实际出现的安全词算 loss，也不是先把 S 里的概率重新归一化再做 KL。每个有效生成位置都比较 S 中全部候选。[§3.4, Eq.(6), p.4；§5.2, p.8]

L=1BM∑b=1B∑m=1M1T(b,m)∑t=1T(b,m)Lt(b,m)

这是把原文 Eq.(7) 的期望写成有限平均的说明式：B 是 batch 指令数，M 是每条指令的 rollout 数，T 是每条回复的有效长度。先按回复长度平均，再平均轨迹；padding 不参与，长回复不会仅因 token 多而自动权重更大。[§3.4, Eq.(7), p.4]

官方实现用 torch.no_grad() 算教师，先 gather 安全 token 的 log-probability，reverse 分支调用 kl_div(teacher_logps, student_logps, log_target=True)。PyTorch 的参数顺序与数学书写不同，这个调用对应学生对教师。离散生成序列作为输入重新前向求梯度，代码没有用标量安全奖励、优势函数或 PPO clipped objective；不能因底层训练器继承相关工具就把它写成 GRPO。[code d9f7822 · distil_trainer.py:2035–2206]

为什么不重新归一化？以及它并非标准 KL

解释性推导：相对形状 + 绝对质量

设 a=Σv∈Spₛ(v)、b=Σv∈Spₜ(v)，即两模型给 S 的总概率质量；qₛ(v)=pₛ(v)/a、qₜ(v)=pₜ(v)/b 为子集内归一化分布。则原式可分解为：

FS=aDKL(qs∥qt)+alogab

这由 pₛ=aqₛ、pₜ=bqₜ 代入 Eq.(6) 直接得到，a、b 为正。子集重归一化会丢掉 a、b，只匹配 S 内比例；原式还带总质量信息。但原式是 KL 求和的局部项，缺少补集与其他修正项，不保证非负，也不保证在 pₛ=pₜ 时取得其全局最小值。因而“保留质量信息”比“严格锚定相等绝对概率”更准确。[根据 Eq.(6), p.4 与 §5.2, p.8 推导]

分析判断：局部监督不意味着局部参数更新

S 外项没有显式 loss，但 full-vocab softmax 共用分母，隐藏层和输出权重也共享。若 z_w 是 S 外一个 logit，在固定教师与前缀条件下，链式求导得到下面的说明式：

∂FS∂zw=−ps(w)(FS+a)

FS 是上面的局部损失，a 是学生给 S 的总概率质量，w∉S；这个梯度通常不为零，展示了概率耦合。因此“只更新安全 token”应理解为限制求和域，不能理解为冻结补集 logits、神经元或模型参数。

[根据 Eq.(6), p.4 的 full-vocab softmax 求导]

11 · 限制、复现边界与可复述结论

作者明确限制：方法依赖基座已有拒绝能力；只测试了上述指令模型且规模不超过 10B；尚未验证更大模型、VLM 或 diffusion language model。不能直接把它用于纯预训练 checkpoint 并假设同样有效。[§7, p.9]

本次分析判断

可靠结论是：局部候选词表损失在这些设置中能减少蒸馏对通用能力的扰动，Qwen 安全表现尤其有说服力。更强的“完全解耦”或“消除 alignment tax”尚缺证据。评测依赖自动裁判，困难集 ASR 和误拒绝仍有残余；没有置信区间、同数据预算完整消融或端到端成本表，不能独立把改善归因于每一组件或换算成明确算力节省。

[Tables 1–7, pp.4–8,13–14；Table 12, p.17；§7, p.9]

复现材料缺口：本次已核实论文和固定代码，但没有 GPU 训练、评测日志核验或数据去污染审计。论文配方与公开脚本的挖掘集合和开关命名存在需澄清差异；最终注入层号/方向、过滤后样本量、安全 token ID 清单及产生主表的运行配置要由实际 run artifacts 对齐。正文的“少于基线 1% 数据”是作者按训练样本规模的比较，并非严格同预算因果实验。[§4.1, p.5；Appendix A.1, p.12；固定官方代码核对]

可以复述的方法：先把基座拒绝方向加到教师残差流；让教师沿无害指令写拒绝前缀，使用同前缀的教师/基座概率比投票找到 S；再让学生在有害指令上自己生成，用教师在学生前缀上的完整词表概率切片指导它；只对 S 求局部 reverse-KL 项，不在 S 内重新归一化；最后部署学生。关键是两个阶段的轨迹来源、词表维与时间维的区别，以及“局部损失不等于局部参数”。

自测：能否把机制讲给别人？

为什么教师可以过度拒绝而学生较少误拒绝？前者制造对比信号；学生只在有害指令上做局部蒸馏。误拒绝表支持大幅减轻，但不证明完全不增加。

安全 token 没出现在 rollout 中，还会有 loss 吗？会。loss 比较每个有效前缀上的 S 中所有候选概率。

H 与回复最大长度是否相同？不同；H 只控制前置挖掘窗口，蒸馏使用有效学生回复位置。

为什么不能称目标为标准子集 KL？切片没有重新归一化，缺少完整分布的非负性保证。
